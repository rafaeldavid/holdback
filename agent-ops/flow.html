Agent ops

Four lanes feed in: tickets, agent feedback, the roadmap and usage telemetry. Merged PRs come out. Deterministic gates run first, a second model family reviews at milestones, and Rafa holds the control plane and everything outside the repo.

    Cross-family review

    Anthropic models write the code; DeepSeek reviews it, with OpenAI as the fallback. Two families make different mistakes. This is the panel rule of ADR-0006 applied to the repo itself.

    MilestoneReviewersBlocks on
    tier 2 PRa model other than the author + DeepSeekthe merge
    control planeFable 5.1 + DeepSeek; Rafa mergesthe merge
    schema version bumpOpus 5.5 + DeepSeekthe merge
    judge registry changeFable 5.1 + DeepSeekthe merge
    ADRDeepSeek critique attachednothing: input to Rafa
    phase exitred teams: Fable 5.1, DeepSeek, GPT familythe exit claim
    before a deployDeepSeek, on the diff since the last deploynothing: the deploy is already gated
    mainnetexternal auditRafa
    • Blocking finding: a file and line, the rule or litmus test it breaks, and a reproduction.
    • A run decides, not a vote: the verifier runs the reproduction once. If it reproduces, the finding blocks; if not, it becomes a backlog row. A vote would let two Claude seats outvote DeepSeek.
    • No re-rolls: never re-run a reviewer to get a different verdict.
    • Abstain: output that does not fit ReviewVerdict counts as ISSUES. Two abstentions, or two refuted findings from one family, on one PR go to Rafa.
    • Outage: DeepSeek down, a GPT-family model reviews; both down, Rafa decides. No provider can block a merge alone, or pass one alone.
    • Blind: the xreviewer gets the diff, the acceptance criteria and the litmus tests, never the PR's self-assessment.
    • Theater check: flag a family that agrees with self-assessments over 95% across 20 PRs; plant canary defects monthly (both thresholds guessed).
    • Why in CI: agents share one GitHub account, so any of them can post "PASS". None can forge a status from a pull_request_target workflow on main.
    • Today "Rafa merges" is a convention: the ruleset needs 0 approvals (measured). It becomes enforced with a fleet GitHub App and code-owner review on tier 3.

    3 → 5 lane cap, before and after T-034 (inferred: 20 jobs ÷ 9 per run)
    • T-034: cache the forge build; filter paths at the job level so check and gitleaks always report; run TLC only when formal/** changes; add verify --affected.
    • T-035: fix the receipt stall at its root. testTimeout: 30_000; timeouts detect hangs, they do not assert.
    • T-036: /merge-pr waits without polling and reruns a listed flake once; a second failure is real.
    • Limits: one full pnpm verify per machine, since two in parallel push tests past their timeouts (measured, docs/backlog.md). Each flake entry links its fix task and expires after 14 days. A listed flake that fires twice in a day pauses its lane.
