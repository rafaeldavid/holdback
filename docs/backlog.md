## Judgment defenses

| Item | Source | When it matters |
| --- | --- | --- |
| **Full judgment report, verifiable inference, auto-tuning from outcomes (T-308).** (1) *Report:* the adjudicator produces the whole judgment end to end: each deterministic check and its result, the screen, each judge's full reasoning where the provider exposes it (some return only a summary), each verdict, and the aggregation. It is a separate artifact hashed into the judgment record; the verdict keeps its capped rationale, since the cap is a defense. It is sealed to the parties and the adjudicator by default (D35, D40) and released only after the decision, so a seller cannot tune deliveries against live reasoning. The reasoning derives from untrusted deliverables, so the report is data, never instruction, for any reader, like the screen report (ADR-0021; threat T22). Appeal judges never receive the first instance's reasoning, so it cannot relay an injection or correlate errors. (2) *Verifiable inference:* proof that the pinned model produced this output from this input. This would close residual 8 (`docs/neutrality.md`; ADR-0014 §4, attested judges; it subsumes the "Response attestation" row below). The target is provable inference: a zkSNARK bound to a commitment to the judge's weights, which the parties, the adjudicator and anyone they disclose the report to can check on a CPU without the weights. Anthropic's FlashProve (2026-11-02, Apache 2.0, https://www.anthropic.com/research/provable-inference) proves Llama 4 Maverick at about 110 tokens/s on one H100, with about 19 MB proofs per 1,024-token request that verify in about 17 s. Fit for ’crow: the registry entry carries the weight commitment beside the pinned model ID; judges decode greedily on the integer model the proof covers; proving runs after the decision, inside the appeal window; a missing or failing proof is an appeal ground backed by the bond; the judgment record stores proof hashes, not proofs. A proof covers output tokens, so it can cover the reasoning as well as the verdict, and the report in (1) is then proven, not asserted (inferred). Open for the ADR: whether a missing proof is an appeal ground that sits with D28's burden on the appealing buyer, a `neutrality.*` fixture for a prover that refuses or goes offline, and the live panel's Anthropic seat, which rejects non-default sampling and has no published weight commitment (`docs/decisions/registry-log.md`). Limits today (corrected by the research pass): one model shape (Llama 4 Maverick's text transformer), not MoE models as a class; a 1,024-token window that holds prompt, reply and padding together, which a judge prompt cannot fit and should not be split across; greedy decoding on an integer model; open weights only unless a provider publishes a commitment; unmaintained and unaudited; 110 tokens/s counts window tokens (39.1 reply tokens/s, under the looser clipped-gap policy). The Anthropic seats can never be proven this way, and their reasoning is a summary written by a different model. Interim options: TEE attestation (with ADR-0020 §5's TEE.fail caveat), provider-signed responses, and re-execution by a party holding the plaintext where inference is reproducible. (3) *Auto-tuning:* an automated loop proposes and evaluates candidate parameters on each batch of outcomes: calibration runs (T-301), overturned appeals and red-team results. It tunes the model mix in the registry, and the thresholds, prompts, aggregation rule and sampling rate in the policy. Only promotion is gated. A candidate ships as a new registry version or a new policy (`policyId`/`policyHash`); each commitment binds both hashes, so an open deal never changes. T-305's promotion workflow extends to policy releases. Pinned models and no re-roll after a verdict still hold, and the promotion gate itself (2% false accept, 5% false reject, no red-team accepts) stays outside the loop. Each adjudicator tunes its own registry and policy, and the parties choose the adjudicator, so there is no central tuner. Guards against Goodhart effects and appeal poisoning: a held-out red-team set, a capped step per release, and a published log of aggregates only, with no private-deal content. Research pass done (`docs/research/t-308-judgment-report-provable-inference.md`); ADR-0027 (Proposed) proposes per-seat attestation kinds with independent anchors and a party-chosen minimum; post-hoc proofs that never gate settlement; a missing proof as a fixed penalty from the adjudicator's own junior stake, paid only for plain absence, with every other proof problem as evidence and the merits never re-tried; free text that can quote the work following the hold, in the report and the record; and a promotion gate outside the loop. Reviewed by the `reviewer` role and a Sonnet red team on PR 115; still needs a different-family review.
