# API review: agents as the primary callers (2026-11-02)

Independent review of the ’crow / Holdback operator API, with a research pass on API practice for LLM agents as callers. Scope grew during the review at Rafa's request: conformance with D1–D38 and the Accepted ADRs, stubs for planned capabilities, a "Feedback and issue reports" design, "Minimal telemetry for the MVP", an end-to-end-encryption check against ADR-0024 §1, and a "Simplify" list. The lens throughout: an agent with only an HTTP client, an EIP-712 signer, NaCl and the published docs (no SDK, no MCP, no `examples/agent.ts`) completing a deal first try, over an API that stays simple and unified.

**Method.** Read: `docs/api.md`, `spec/openapi/paths.json` and the generated document, `spec/schemas/*`, `site/llms.txt`, `examples/agent.ts`, `examples/verify.ts`, `apps/operator/src/{server,prepare,guards,idempotency,read-auth,policy}.ts`, `apps/demo-cloud/src/{world,worker}.ts`, `docs/decisions-today.md`, ADR-0017/0023/0024/0025/0026, `docs/plan.md`, `docs/backlog.md`, T-015/T-025/T-027 and the two reviews that touch the API. Measured live (both nodes, 08:53–09:12 UTC): discovery, status, `/llms.txt`, `GET /`, error shapes for bad input, page sizes, a hash-only prepare, the SSE stream, and one full checks-only deal with `apps/demo-cloud/scripts/deal.ts` (Released 3.0 s after delivery, final at 65 s, 10 receipts per operator, operator fee 10000 base units paid). Labels: **measured**, **inferred**, **guessed**. Earlier friction fixed by T-025 and T-027 is not re-reported.

## 1. Verdict

The API is already closer to "agent-native" than most payment APIs: every state change is prepare → verify → sign → submit with a plain-language `check` list, nonces the agent chooses, a dry run, RFC 9457 problems that carry the `Request-Id`, idempotency on every write, untrusted-text markers, and a one-page `llms.txt` that a repository walkthrough proves sufficient for the checks-only happy path. The protocol guarantees (operator never signs, verify-before-sign, two-operator reads) are visible in the API's shape, not bolted on. What stands between an outside agent and a first-try deal today is not the protocol but drift and hidden knowledge: the published agent guide is stale against the live nodes on the one dimension that can strand a hold (private deals at schema 0.8), the two routes the happy path needs first (`POST /v1/faucet`, adjudicator roles from `GET /`) are outside the OpenAPI document, the operator's own `/llms.txt` points at a repository path instead of a URL, errors are actionable only as prose, and a handful of EIP-712 encodings exist only in `examples/verify.ts`. All of that is fixable with docs and small operator changes; none needs a protocol change. Against Rafa's simplicity principle the surface has accreted duplicates (three discovery documents, two `llms.txt`, two faucets, two `chainId` encodings, two names for the fee, prose-only errors) that can be consolidated without weakening a guarantee.

## 2. Simplify

Fewer endpoints, concepts and moving parts, with the guarantees intact. Each item is expanded in the findings or the conformance table.

1. **One discovery document.** Make `/v1/status` return the `/.well-known/holdback.json` body (one `chainId` encoding) and fold the demo's `GET /` facts into it: adjudicators with roles, token decimals, the faucet, limits, feedback contact. Today an agent must read three documents to start (measured: `/.well-known/holdback.json`, `/v1/status` with `chainId` as a string, `GET /` with roles).
2. **One `llms.txt`.** The operator's `/llms.txt` should link the canonical guide (`https://escrow.stream/llms.txt`) and the raw `docs/api.md` URL instead of being a second, different text that names a repository path.
3. **One faucet.** `POST /v1/faucet {address}` in the OpenAPI document under a `demo` tag; retire the operator router's `/v1/test/faucet {address, amount}` (server.ts:529, 729) which no public node serves.
4. **One funding path on the happy path.** Keep `agree` with `fund` (and `operatorFee`); label `/holds` and `/fund` as advanced in the document, since both relay a funding without the fee (ADR-0023 residual, backlog).
5. **Notices in the body, not headers.** Replace `Holdback-Notice` (set in `apps/demo-cloud/src/world.ts:313`, absent from `spec/openapi.json`, unmarked as untrusted, measured on a 400) with `notices: string[]` marked `x-holdback-untrusted` in `Prepared` and in the write response; later the D31 advisory `warnings[]` goes in the same place.
6. **One error scheme.** Keep the `type` vocabulary, make each `type` resolvable, and add typed extension members where an agent must branch (§4, F4); stop reusing `invalid_state` for 500 and `invalid_cursor` for a bad `limit`.
7. **Require caller nonces in prepare.** Delete the default-nonce derivation (`prepare.ts:153-157`, `holdback/prepare/v1/…`) and the nonce round-trip in `defaults`; the docs already tell agents to send their own. One hidden computation fewer; `defaults` keeps only times.
8. **One timestamp format** (whole seconds, `Z`) in every read model field; today `appealBy` carries `.000Z` beside `settledAt` without (measured).
9. **One name for the fee:** `fees.operator` (status and discovery); drop `operatorFee` from `GET /` once folded.
10. **One version story, in one paragraph:** `apiVersion v1`, `info.version 0.2`, `schemaVersion 0.8` and domain `0.6` are four numbers an agent meets in its first minute.
11. **Shorter OpenAPI descriptions** with the "verify before you sign" lists moved to one linked section, and a `core` tag on the dozen happy-path operations so tool generators can filter.

Do not simplify: the two signatures in agree-and-fund (and the third for the fee), the three-adjudicator slate, the dry run, receipts, the `check` list, and two-operator reads. Each carries a guarantee.

## 3. What the API already does well for agents

- **Prepare → verify → sign → submit** with `sign[].slot`, `digest`, `submit.body`, `check[]` and `defaults` (prepare.ts:61-72). No surveyed payment API returns a readable `check` beside the message to sign; the nearest are x402's `description` and ERC-7730's wallet-side rendering (research, measured: https://github.com/coinbase/x402/blob/main/specs/x402-specification-v1.md, https://eips.ethereum.org/EIPS/eip-7730).
- **Agent-chosen nonces, pinned domain and types**, and refusal guidance that matches Safe's "recompute the hash yourself" practice (https://hackmd.io/@safe/verify-transactions, measured).
- **Dry run** that accepts the exact prepared body with `null` slots (T-025; measured 409 `invalid_state` on a Released deal rather than a crash).
- **RFC 9457 problems** with `instance: urn:holdback:request:<Request-Id>` on every error (measured), `Retry-After` on 429 (measured: `retry-after: 3130` on a repeat faucet call).
- **Idempotency** on every write, 409 on a mismatched body, documented divergence from the IETF draft's 422 (api.md:21; draft-ietf-httpapi-idempotency-key-header-08 recommends 422 for mismatch and 409 for in-flight, measured).
- **`x-holdback-untrusted`** on 40 schema fields plus `Problem.detail`, `Prepared.check` and discovery `notes` (measured): ahead of practice, since no standard marks untrusted fields (research, inferred; nearest is MCP's "annotations are untrusted").
- **Discovery** at `/.well-known/holdback.json` (RFC 8615) with `settlementTime`, `apiBaseUrl` and the fee schedule up front; `Link: …/terms; rel="terms"` on the state read (measured).
- **Small reads:** state ~700 bytes, terms 1,952 bytes, 10 events 8,520 bytes (measured).
- **Honest limits** stated in `llms.txt` and `notes`; planned routes kept out of `paths` and listed under `x-holdback-planned` (13 entries live, measured) so no generated tool 404s.
- **Test vectors** for the envelope, and a published walkthrough that built every message from `llms.txt` alone (T-027 evidence).

## 4. Findings, ranked by impact on a first-try deal

Classification: **[protocol]** needs an ADR and a schema version bump; **[operator]** API or operator change within v0.2; **[docs]** docs only.

**F1. The published agent guide is stale on private deals, and a private offer on the demo cannot be judged. [docs] + adjudicator lane.** `site/llms.txt:315` says "Schema 0.7" and `:344` says private deals are "schema 0.8, not yet on these nodes"; both live nodes answer `Holdback-Schema-Version: 0.8` and `schemaVersion: "0.8"` (measured), and `POST /v1/prepare/offer` with `hashOnly: true` answers 200 with `disclosure.level: private` (measured). The T-207 Handoff says the sim primary "accepts sealed offers without reading them, and would fail at decision time", so an agent following `docs/api.md` "Private deals" on the public demo funds a hold that no adjudicator can decide and recovers only by early accept, mutual settlement or `reclaim` after `deliverBy`. `docs/api.md:3` still says v0.7 and `:387-388` names the workers.dev URLs. **Recommend:** rebuild and republish `llms.txt` from the live version; until the adjudicator slice lands, the demo adjudicator should decline sealed offers it cannot judge (D29/D32: an adjudicator may decline terms it won't run) and the operator should add a `notices` entry on a private prepare ("on this demo a private deal settles only by early accept or mutual settlement"). Source for "state limits where they bite": T-025's own lesson.

**F2. The first two things an agent needs are outside the OpenAPI document. [operator]** The happy path starts with `POST /v1/faucet` and the adjudicator roles, both served by the demo Worker, not the operator router, so neither is in `/v1/openapi.json` (backlog, T-026). Roles exist nowhere else: the registration (`GET /v1/adjudicators/{address}`, measured keys) has no `roles`, and `/v1/adjudicators` lists three equal entries. An agent that generates tools from the document, as LangChain's `reduce_openapi_spec` and LlamaIndex's OpenAPI toolkit do from `paths` only (measured), cannot fund itself or build the slate. **Recommend:** put the faucet in the document under a `demo` tag and publish adjudicator roles in discovery (`adjudicators: [{role, address}]`) or as `roles` in the registration (the T-017 backlog row). Prior art: A2A puts everything an agent needs to start in one card at `/.well-known/agent-card.json` (measured, https://a2a-protocol.org/latest/topics/agent-discovery/).

**F3. The operator's own `/llms.txt` cannot be followed. [docs]** It links the OpenAPI document and discovery, then names "docs/api.md in the Holdback repository" and "docs/quickstart.md in the Holdback repository" with no URL (measured on both nodes; `apps/operator/src/openapi/index.ts:38-39`). The guide that works is `https://escrow.stream/llms.txt` (29,523 bytes, ~7–8k tokens, measured). llmstxt.org requires link lists under H2 headings (measured, https://llmstxt.org/). **Recommend:** link the canonical guide and the raw `docs/api.md` URL; add `rel="alternate" type="text/markdown"` on the site page.

**F4. Errors are actionable only as prose. [operator]** Problems carry `type` (a bare token), `title` (the type again), `status`, `detail`, `instance`. RFC 9457 defines `type` as a URI reference and says consumers "SHOULD NOT parse the detail member" (measured, https://www.rfc-editor.org/rfc/rfc9457.html); as a relative reference, `invalid_terms` resolves against the request URL. Everything an agent must branch on sits in prose: the state in 409 (`"commitment is Released"`, measured), the fee amount and address in 402 (server.ts:569-573), the retry hint in 429, the missing fields in 400. Overloads: a 500 is typed `invalid_state` (server.ts:439), a bad `limit` is `invalid_cursor` (measured), an unknown prepare kind is 404 (measured). **Recommend:** keep the short vocabulary but make `type` resolve (`https://escrow.stream/problems/<type>`, a page per type generated from `PROBLEM_TYPES`) and add typed extension members: `state` and `needs` on `invalid_state`; `fee: {to, token, amount}` on `payment_required`; `retryAfterSec` on `rate_limited`; `field` on `invalid_terms`; `alternatives` (another operator, direct submission) on `relay_refused` and `payment_required`. Add `internal` (500) and use `invalid_terms` for malformed query parameters. Problem types live in `@holdback/core` and the OpenAPI document, not `spec/schemas`, so this is an operator change; extension members are additive. MCP's rule that error results should "contain actionable feedback that language models can use" is the same instinct (measured).

**F5. Two timestamp formats in one object. [operator]** `appealBy: "2026-11-02T08:02:07.000Z"` beside `settledAt: "2026-11-02T08:01:07Z"` on the live list (measured); backlog "Mixed timestamp formats" (T-006 review). An agent comparing strings, or hashing a read model, fails. **Recommend:** normalize to whole seconds at the read model; no schema change (`date-time` allows both).

**F6. Encodings an agent needs exist only in `examples/verify.ts`. [docs]** (a) The default nonce is `keccak256("holdback/prepare/v1/" + JCS(message without nonce))` (prepare.ts:153-157); `docs/api.md:80` omits the prefix. (b) EIP-712 encodings with `has*` flags and zero defaults: `MutualSettlement {hasDelivery, deliveryHash: 0x00…}`, `ReadToken {hasAudience, audience: 0x00…}`, `Delegation.scope {hasCategories, categories: []}` (verify.ts:106-111); `llms.txt` documents only `Delivery.unlock {kind: "", round: 0}`. (c) The private-deal recipe, the ReadToken header and the `Delegation` checks are in `docs/api.md` but `llms.txt:350` points to the repository. An agent on the site alone can run the checks-only happy path and nothing else. **Recommend:** an "Encodings" subsection in `llms.txt` listing every `has*`/zero rule and the settlement, appeal, early-accept, ReadToken and Delegation messages; or make the recipe moot for nonces by requiring them (Simplify 7). Settlement and appeal are the most likely second deal an agent attempts.

**F7. The OpenAPI document is too large and too wordy for tool use as it stands. [operator]** 160,616 bytes, 40 operations, 90 schemas (measured); descriptions of 1,462 chars (`prepareOffer`), 1,456 (`prepareAgreeAndFund`), 908 (`prepareAppeal`) and 14 more over 300 (measured). OpenAI Actions cap each description at 300 chars and payloads at 100,000 chars, and the community-reported operation cap is 30; OpenAI's function-calling guide says "aim for fewer than 20 functions"; Anthropic recommends 3–4 sentences per tool and consolidating operations (all measured; URLs in Sources). **Recommend:** keep one document; move the "verify before you sign" lists to one `externalDocs` section (the `llms.txt` §4 list), cap descriptions at 300 chars, and tag the happy-path dozen (`getDiscovery`, `getAdjudicator`, `getClub`, `prepareOffer`, `submitOffer`, `getCommitmentTerms`, `prepareAgreeAndFund`, `submitAgreement`, `uploadCiphertext`, `prepareDelivery`, `submitDelivery`, `getCommitment`, `listCommitmentEvents`, `listReleasedKeys`) with `x-holdback-core: true`.

**F8. Rate limits are unpublished. [operator] + [docs]** ADR-0017/D13 promised `/v1/status` with "the caller's limits"; status carries none (measured). The demo's budgets (120 writes, 1,200 reads per minute per client, `world.ts:202`; faucet 1 per address per hour, 10 per client per hour) appear only in `notes` or nowhere; 12 reads in about a second all passed (measured). The IETF `RateLimit` fields are still draft-11 (measured), so deferring the headers is right. **Recommend:** `limits: {reads: {perMinute}, writes: {perMinute, per: "signer"}, faucet: {...}}` in discovery, and the same sentence in `llms.txt` Conventions.

**F9. Idempotency retention and refusal semantics are undocumented. [docs] + [operator]** The store keeps successes only (idempotency.ts:37), lives in memory and is lost on restart (backlog), and keys share one namespace across signers (backlog). Stripe publishes "at least 24 hours" and replays saved errors (measured, https://docs.stripe.com/api/idempotent_requests). **Recommend:** one sentence in Conventions ("refusals are not stored; a key is remembered for the node's lifetime, at least N hours once persisted"), and scope the fingerprint by signer address when a signer is known.

**F10. Docs imply an SDK or MCP is coming. [docs]** `docs/api.md` "SDK (TypeScript, internal)" and "MCP wrapper (Phase 6)" (api.md:406-412), and `docs/plan.md` Phase 6 "MCP server wrapping the SDK", read as a roadmap; Rafa's constraint is "later, only on demand". Conventions also describe SDK behaviour ("The SDK waits once, for at most 2 seconds", api.md:13) where an agent needs its own instruction. **Recommend:** reword both to "later, on demand", and phrase Conventions for the HTTP caller.

**F11. Prepare's convenient path defaults to the least private level. [operator], see C11.** `POST /v1/prepare/offer` without `hashOnly` signs `disclosure.level: public` (api.md:19; prepare.ts:257-320), while ADR-0024/D34 make `private` the default. **Recommend:** make `disclosure` a required input of `prepareOffer` with the tradeoff in its description (D31: a parameter, not a default), so an agent chooses.

**F12. Default EarlyAccept/settlement expiry and `attempt` are operator-chosen but invisible in `llms.txt`.** [docs] `expiresAt` defaults to settlement time + 3600 s (prepare.ts:430, 493); `attempt` from state. Covered in OpenAPI descriptions, not in the guide. Add one line each when F6 lands.

**F13. CORS is absent.** [operator, low] `OPTIONS /v1/status` is 404 (measured). Irrelevant to server-side agents; blocks browser-hosted ones. Add a permissive CORS layer only if a browser client appears.

## 5. First five

1. Republish `llms.txt` from the live version and fix `docs/api.md` (v0.8, `api.escrow.stream`, private-deal caveat); have the demo adjudicator decline sealed offers it cannot judge (F1).
2. Put the faucet and adjudicator roles where tools find them: discovery document plus a `demo` tag in the OpenAPI document (F2, Simplify 1 and 3).
3. Make problems machine-actionable: resolvable `type`, `state`/`needs`/`fee`/`retryAfterSec`/`field` extensions, `internal` for 500 (F4).
4. Fix the operator `/llms.txt` links and add the "Encodings" subsection to the guide (F3, F6).
5. Publish limits and idempotency retention in discovery and Conventions; normalize timestamps (F5, F8, F9).

## 7. End-to-end encryption: the built API against ADR-0024 §1

ADR-0024 §1 allows the operator: the settlement view and the full struct a party relays; the signer address of each write, verified before a budget is charged; ciphertext sizes, timing, client IP, who reads which deal. What the built API lets an operator read or log beyond that today:

| Surface | Today | Verdict |
| --- | --- | --- |
| Bodies at level `public` | Full terms in the offered event, the index, `/terms`, prepare inputs | By design, but `public` is the default of the easy path (C9) and the only level the demo adjudicator can judge (F1) |
| Judgment records | Held and served in the clear; `private` only hides them behind a ReadToken | Gap against §2 until sealed records land (C5) |
| Idempotency store | Full response bodies (state plus receipt) in memory, fingerprints as hashes (idempotency.ts:16) | Settlement view only; fine. Document lifetime (F9) |
| Operator logs | `LogEntry` has no body, no IP: requestId, method, path, status, ms, traceparent (server.ts:74-82). The demo Worker passes `cf-connecting-ip` as the throttle client (worker.ts:99), kept in in-memory windows. Workers observability is enabled on both nodes (wrangler op1/op2 `observability.enabled`), so Cloudflare keeps invocation logs for 3 days on the free tier (measured, Cloudflare docs); paths carry commitment IDs and `?recipient=`/`?party=` addresses (settlement-view data) | Acceptable; never log `Authorization` (ReadTokens name the viewer) or bodies; truncate or drop IPs in anything persisted (§9) |
| Error `detail` and `check` text | Echo addresses, IDs, states, amounts, hashes; no body content (prepare.ts, server.ts) | Within the view |
| Events | `actor` (signer) and `submittedVia` (relaying operator) on every event (measured) | A small metadata leak not in §1's table: operator–party affinity. Keep for receipts, or hash it |
| Rate-limit buckets | Keyed by the body's signer before verification | Mismatch C4 |
| Faucet (demo) | Address, IP window, time | Demo only; already minimal |
| Funding and feedback stubs | Nothing yet | Design per §1 (§8, §9) |

Remaining metadata leaks and mitigations: client IP and timing (Cloudflare terminates TLS; mitigation: no IP at rest beyond abuse windows, no IP-based blocks beyond the faucet, so relays and Tor-style access work); amounts, addresses, deadlines, hashes on the settlement view (public by design, residual 9; confidential amounts deferred with D4, Prividium fragment T-208); who reads which deal (ReadToken viewer; mitigate by not logging `Authorization` and by list scoping); the relaying operator (`submittedVia`); ciphertext sizes (`bytes` is signed; a seller can pad to size buckets, a docs-only tip under D32); funding linkage (residual 11); the operator-fee transfer, which links a buyer address to an operator on the public ledger. **MVP must have:** no body logging, `Authorization` never logged, IPs only in memory, telemetry from settlement-view fields only and aggregated (§9), `disclosure` as an explicit choice (F11). **Later:** sealed judgment records and the adjudicator slice (T-207), ReadToken list scoping, padding guidance, T-208, confidential amounts.

## 8. Feedback and issue reports

**Where it sits.** An operator service, not the protocol: each operator runs its own, like the fee and the faucet; nothing on the settlement layer changes. The maintainers publish one address and encryption key for protocol-level bugs, and an operator may forward or copy a report there with the reporter's consent (a `shareWithMaintainers: true` flag).

**Prior art.** Sentry: an event has an `event_id`, `fingerprint` for grouping, `release`/`environment`, a `request` context, and user feedback attaches to an `associated_event_id`; ingestion answers 429 with `Retry-After` (measured, https://develop.sentry.dev/sdk/data-model/event-payloads/, https://develop.sentry.dev/sdk/telemetry/feedbacks/). GitHub issue forms require named fields (steps, expected, actual, environment) and the REST API answers 422 when "spammed" (measured, https://docs.github.com/en/rest/issues/issues#create-an-issue). Zendesk tickets: `external_id` for linking, a `new → open → pending → solved → closed` lifecycle, public comments versus internal notes (measured, https://developer.zendesk.com/api-reference/ticketing/tickets/tickets/). Apple and Chromium crash reports auto-attach version, OS and stack, and scrub paths (measured). RFC 9116 publishes a reporting contact at `/.well-known/security.txt` (measured). LangSmith and Braintrust attach feedback to a run id with score plus comment (measured). The pattern that transfers: a correlation id the client already holds, a small required schema, server-side auto-attachment, grouping by fingerprint, a visible status, and hard ingestion limits.

**Design (two routes, one message, existing crypto).**

- `POST /v1/feedback` → 202 `{id, status: "received", fingerprint, duplicateOf?, retentionUntil}`. `GET /v1/feedback/{id}` → `{id, kind, status, fingerprint, duplicateOf?, replies: [{at, text}], fixedIn?}`. No list route in the MVP: the `id` is the handle, and anonymous reporters could not list anyway.
- Body: `kind` (`bug` | `feedback` | `docs` | `feature`), `summary` (≤200 chars), `detail` (≤4,000 chars, Sentry's 4,096 rule), `requestId` (the failing request's `Request-Id`, uuid), `idempotencyKey?`, `commitmentId?`, `observed?`, `expected?` (≤500 chars each), `schemaVersion` (the agent's pinned), `client?` `{name, version, model?}`, `docsUrl?`. Every reporter field is `x-holdback-untrusted`.
- Attribution, optional: `signer` plus `signature` over an EIP-712 `Report {reporter, bodyHash, nonce, expiresAt}` (one new type, additive, domain stays 0.6 by ADR-0023's rule; operator-level like `Prepared`, so no `spec/schemas` bump). Unsigned reports are accepted with tighter limits.
- Confidentiality, optional: discovery publishes `feedback: {url, encryptionPublicKey, maintainers: {address, encryptionPublicKey}}`; a reporter that must include deal details sends `sealed: {ciphertext, envelopes[]}` built exactly like a delivery (AES-256-GCM body, NaCl envelopes to the operator's and optionally the maintainers' key). No new cryptography; `llms.txt` warns: never paste secret keys, plaintext work or terms bodies; the `requestId` is enough for most bugs.
- What the operator attaches automatically: its `LogEntry` for that `Request-Id` (route, status, problem type, ms, traceparent, time), `operatorId`, `schemaVersion`, build commit, settlement head at the time, and, if a `commitmentId` is given, its public state (`escrowState`, `lastEventSeq`). Settlement view only; never bodies. Reports arriving within the log retention window (§9) reproduce without back-and-forth; the 202 says so ("logs attached" or "logs expired, include detail").
- Triage: fingerprint = hash(kind, route, problem type, schemaVersion, normalized summary); a match sets `duplicateOf`. Lifecycle `received → triaged → needs-info | fixed (fixedIn) | wontfix | duplicate`. The operator replies by appending to `replies`; the reporter polls `GET /v1/feedback/{id}`. Reports are data: an LLM may summarize them only as wrapped content, never as instructions, and nothing is auto-executed from a report.
- Abuse: JSON only, body ≤16 KB, unsigned 10 per client per hour and signed 60 per signer per hour with `Retry-After`, a honeypot field as `apps/early-access` uses, retention 90 days (longer only while linked to an open fix), kinds and lengths enforced.
- Where reports land: a private store first (KV or the World Durable Object's SQLite), read by maintainers with `wrangler`; filing public GitHub issues is outward-facing and stays manual behind Rafa's gate; a weekly digest to maintainers is enough at demo volume.

**First slice.** Add the two planned rows now (§6.2). Then a minimal real implementation (KV-backed, the size of `apps/early-access/worker.js`) is better than a stub: agents hit friction today, and the only external dependency is a deploy, which is Rafa's gate anyway.

## 9. Minimal telemetry for the MVP

Principle: every counter derives from what ADR-0024 §1 already lets the operator see, aggregated, with short retention; nothing identifies a party beyond the public settlement view, and nothing holds content. Prior art converges on the same shape: Plausible keeps no raw IP or user agent and rotates a daily salt (measured, https://plausible.io/data-policy); Tor Metrics publishes only aggregate, deliberately imprecise counts (measured, https://metrics.torproject.org/about.html); Google's golden signals and the RED method cover operations (measured); differential privacy buys little at demo volume and matters only for published per-bucket counts (inferred, Apple DP overview). The reported outage when the Durable Object free-tier read quota ran out (coordinator, 2026-11-02; not measured here) is the case for the quota metrics: Free tier is 100,000 DO requests, 5M SQLite rows read and 100,000 rows written per day (measured, Cloudflare pricing).

**MVP list (14).**

Operational (a):
1. Requests per route template × status, per minute (RED rate and errors).
2. Latency p50/p95 per route template.
3. Problems per `type` per route (the error vocabulary doubles as the funnel's refusal reasons).
4. 429s by bucket kind (read, write, faucet).
5. Durable Object requests, SQLite rows read and written per day, against quota, with an alert at 80%.
6. Journal size and replay time on wake (the growth risk in the T-026 backlog).
7. Live judge calls and tokens per day (already in `GET /`).

Product and funnel (b), from settlement events only (no party identity):
8. Deals per stage per day: offered → accepted → held → delivered → decided → final, plus outcomes (released, refunded, escalated, reclaimed, expired, settled).
9. Median time per stage.
10. Prepare → submit conversion per kind, and abandonment stage (offers never agreed, holds never delivered).
11. First-try success: share of fresh signer addresses whose first write succeeded without a 4xx, counted, not listed.
12. Distinct active signers per day (a count; addresses are per deal under ADR-0024 §7 anyway).

Support (c):
13. Per-request log line: Request-Id, method, route template and path, status, problem type, ms, traceparent, operatorId. No body, no `Authorization`, no IP. Retention 7 days at most (Workers Logs keep 3 days free, 7 paid, measured), stated in `llms.txt` so agents report within it or include detail (§8).

Published (d):
14. Weekly aggregate stats (deals, median time to final, success rate), rounded, Tor-style. Publishing is outward-facing: Rafa's gate; a status page later.

**Must not be collected or kept:** raw IPs beyond in-memory abuse windows (≤1 hour), bodies, plaintext, ciphertext contents, `Authorization` headers, user agents, counterparty pairs or per-address histories beyond the public view.

**Where it lives.** Workers Analytics Engine for 1–12 (data points with blobs route/status/type/stage and doubles ms/count; free tier 100,000 points/day, three-month retention, SQL API; measured), Workers Logs for 13 (already enabled), the Cloudflare dashboard for quota; readers: Rafa and maintainers. **Deferred:** differential privacy, per-agent dashboards, Logpush to an external store, a tracing backend, automated status pages.
