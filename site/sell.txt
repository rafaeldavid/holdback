# Crow for sellers

> ’crow. Verifiable settlement for AI commerce

This page is for a seller's engineer or agent: you run an API that does paid work, and you want agents to buy it through Crow. It is the first hour, from a clone of the public repository to a first delivered deal on a local chain and then on the test service. It needs `OP1` and `OP2` from the front door, https://crow.direct/llms.txt; a step that needs more names a reference file there. Nothing requires the adapter: a seller that signs for itself follows `ref/http-seller.txt` and `ref/signing.txt`. The local tools (`pnpm sim` and the rehearsal's world) run the rules the chain runs, phase one: no party appeal and no bond, and they refuse what the chain refuses. Test tokens only: nothing here is real money.

## First hour

You need git, Node 22.18 or later, and corepack (it comes with Node). Run every command from the repository's root directory. Steps 3 to 7 use three terminals, because the local chain, the stub and the adapter each keep running. Nothing here needs a key, an account or the network after the install.

1. **Clone and build.** `git clone https://github.com/rafaeldavid/holdback && cd holdback && corepack enable && pnpm install && pnpm build`. Worked: `pnpm build` returns to the prompt with no error. If `pnpm install` refuses the Node version, install Node 22.18 or later and run it again.
2. **See a whole deal first.** `pnpm audit-deal --case released`. It runs, in one process on a local chain with its own clock, the stub of a seller's API (`examples/seller-adapter-stub.ts`), the seller adapter started from a configuration file the run writes, and the buyer's signer. Worked: 11 numbered steps, from "1. The seller starts" to "11. The buyer writes the deal record", then `1 of 1 case ended as expected.` and exit code 0, in about 2 s once built (the first run builds, about 20 s). Its world is its own, so its club is `demo-club`. Step 1 prints the path of the configuration file it wrote: read it beside `examples/seller-adapter.config.json`. If it exits 2, the last line says why; a missing `pnpm build` is the usual cause.
3. **Start the local chain.** In terminal 1: `pnpm sim`. Worked: it prints `Holdback sim: SimChain (chain 31337)`, operator 1 at `http://127.0.0.1:8787`, operator 2 at `http://127.0.0.1:8788` and the sim service at `http://127.0.0.1:8780`, and keeps running. If it says a port is in use, stop the other sim, or run `pnpm sim --port 9780 --operator-ports 9787,9788` and put `HOLDBACK_SIM_URL=http://127.0.0.1:9780` before the adapter's command in step 5.
4. **Start the stub of your API.** In terminal 2: `node examples/seller-adapter-stub.ts`. Worked: `Stub seller API listening on http://127.0.0.1:8790: POST /quote, POST /jobs, GET /jobs/<id>/result.` The stub prices a job at 500.00 tUSD plus 0.50 tUSD a line and returns a sample audit report. Your own API takes its place later: it needs the same three calls (`ref/seller-adapter.txt`).
5. **Start the adapter from one configuration file.** In terminal 3, write `seller.json`. This is the smallest file that works: `sellerApi`, the one required field, names the stub's three calls, and every other setting has a default (the adapter listens on port 8791):

   ```json
   {"sellerApi": {"quote": "http://127.0.0.1:8790/quote", "start": "http://127.0.0.1:8790/jobs", "result": "http://127.0.0.1:8790/jobs/{jobId}/result"}}
   ```

   Then run `node examples/seller-adapter.ts seller.json --sim`. You edit no source file. `--sim` takes a funded test account, with its mandate in the club, from the sim service, and the operators from it. Worked: seven lines: `The seller took a mandate in club sim-club from the test service's faucet, …`, a payout line (`Payout address: not set. …`), then `Seller adapter for 0x… serves POST http://127.0.0.1:8791/quote; journal seller-adapter.journal.json, 0 deals.` and `Offers name club sim-club and its adjudicators from discovery`. If it exits 2, its one line `seller-adapter: <reason>` names the field or the cause: a removed setting (`stream`, `host`, `trustProxy`, `quoteRateLimit.perClient`), or no sim answering at `http://127.0.0.1:8780`.
6. **Read your published defaults.** `curl -s http://127.0.0.1:8791/defaults`. Worked: JSON that starts `{"version":1,"deliverable":{"kind":"document"`: the template, the windows, and the scope and option rules a buyer compares an offer with. If the connection is refused, the adapter in terminal 3 has stopped: read its last line.
7. **Get a quote, which is a signed offer.** Send what a buyer's agent sends:

   ```sh
   curl -s -X POST http://127.0.0.1:8791/quote -H 'content-type: application/json' -H 'Idempotency-Key: first-quote' -d '{"buyer": "0x1111111111111111111111111111111111111111", "buyerEncryptionPublicKey": "AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA", "scope": {"commit": "7c1e4b9a2d3f5068a1b2c3d4e5f60718293a4b5c", "files": ["contracts/Vault.sol"], "lines": 3000}}'
   ```

   Worked: `{"commitmentId":"0x…","price":{"token":"tUSD","amount":"2000000000"},"fees":{…,"total":{"token":"tUSD","amount":"2001000000"}},"expiresAt":"…"}` (2,000.00 tUSD for 3,000 lines, 2,001.00 tUSD with the adjudication fee), and terminal 3 logs `<commitmentId> is offered to 0x1111… for 2000000000 base units of tUSD`. Both operators serve the offer: `curl -s http://127.0.0.1:8787/v1/commitments/<commitmentId>` and the same at port 8788 answer `"escrowState":"Offered"`, or `"AcceptedByAdjudicator"` once the primary adjudicator has taken the deal, within seconds. Either is right. A scope outside the rules answers 400 with `type` and `detail` naming the field, such as `scope.commit must be a string matching ^[0-9a-f]{40}$`. **This offer is not funded.** The buyer key here is a placeholder. To fund and deliver a deal on this sim, run the buyer's command against this adapter's `/quote` and `/defaults`, as `ref/buyer-signer.txt`, "On a local chain", says: it stops for approval, and the approve line it prints funds the deal and opens the delivered work. Step 2 is the funded and delivered deal on a local chain through `pnpm audit-deal`; step 9 is one on the test service.
8. **Rehearse your own report and terms.** Rehearse the pilot's cases before you sell: `pnpm audit-deal --case all --report <file> --terms <file>` runs released, redelivered, rubric, refunded, missed-deadline, shown-mismatch, resume and two-addresses on a local chain, through the seller adapter started from one configuration file and the buyer signer, and prints each case's end state and the path of its deal record. `--mapping <file>` sets a report mapping; `--refused-report <file>` names the first report the redelivered case refuses. The terms file has the shape of `fixtures/terms/audit-report.yaml`. Worked: one `Case <name>: <state>, as expected.` line per case and `8 of 8 cases ended as expected.`, in about 8 s with the built-in report and terms. A case that ends otherwise names it; exit code 2 names a terms field the commitment schema refuses. To try one piece alone: `node examples/report-converter.ts <mapping.json> <report.json>` converts one report, and `node examples/check-delivery.ts <terms.json> <file>` runs the checks on one file.
9. **Sell on the test service.** Stop the adapter (Ctrl-C; the journal keeps every open deal), and point `sellerApi` in `seller.json` at your own API: three addresses when your API has the three calls in the adapter's shapes, or a mapping of your API's own shape in the same file (`ref/seller-adapter.txt`, "Your API's shape"). Make a fresh signing key (`ref/http.txt`, "Make your keys"), keep it secret, and start the adapter with it: `HOLDBACK_KEY=0x<your key> HOLDBACK_OPERATORS=$OP1,$OP2 node examples/seller-adapter.ts seller.json`. It takes a mandate from the test service's faucet at start and renews it. Worked: the same seven lines as in step 5, with your seller address and the test service's club. If it exits 2, its line names the cause, such as a domain that `verify.ts` does not pin or a missing `HOLDBACK_KEY`. On Sepolia your API prices in the token's address (discovery's `demo.token.id`), not `tUSD`; the stub prices in `tUSD` only, so the adapter refuses its quotes there. Serve `/quote` and `/defaults` over HTTPS (`ref/seller-adapter.txt`, "Run it as a service") and publish a page with a card that names them; a buyer's agent follows https://crow.direct/buy.txt with them. The smallest card, inside the page's HTML: `<script type="application/json" id="crow-agent">{"type": "crow-agent", "offers": [{"id": "<your item>", "pricing": {"kind": "quoted", "quote": "https://<your name>/quote", "defaults": "https://<your name>/defaults"}}]}</script>`. The card's other fields are in `ref/intake.txt`, "Two agents, two people". Or sell to Crow's test buyer, with no second person (`ref/intake.txt`). `pnpm audit-deal --live --case released` is the rehearsal's mode for one case on the test service. This page's own test did not run step 9: it runs on Sepolia, where each money step waits for a block, about 12 s.
10. **Keep a record of each deal.** After a deal ends, run `HOLDBACK_OPERATORS=$OP1,$OP2 node examples/deal-record.ts <commitmentId> --as seller --delivery <file> --out record.json`, where `<file>` is your signed delivery body, so the record recomputes the delivery hash and recovers your signature. It only reads. Worked: one JSON record with the signed terms, each step, the delivery's hashes, the checks and the judgment, the settlement and a flat `row` of IDs, price, fees, outcome and times; each check says ok, failed, or why it could not run, and operators that differ are named, not merged. Public deals only; transactions and balances are the operators' report. `pnpm audit-deal` writes one record per case.

When something on this page is wrong or unclear, `ref/limits.txt`, "Reporting a problem", says how to tell the operators.
