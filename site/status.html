About these checks

Which services does the status page check?

Five: the site (crow.direct), operator 1 (api.crow.direct), operator 2 (api2.crow.direct), Crow’s test seller, and Ethereum Sepolia, the network where deals settle. An operator is a server that relays the parties’ signed messages and serves Crow’s API.

Source: site/trust.mjs

How is each service checked?

With one plain GET per service. The reader’s browser reads the site, the test seller and Blockscout directly. The operators send no CORS header, so the site’s Worker reads each operator’s /.well-known/holdback.json from Cloudflare’s network, and the browser reads the Worker’s answer at https://crow.direct/status/operators.json.

Source: apps/site/status.js; site/trust.mjs

What does each state mean?

Operational: the service answered as expected. Down: the service answered an error, answered with the wrong body, or did not answer in time. Degraded: Sepolia’s newest block on Blockscout is more than 120 s old; Sepolia normally makes a block about every 12 s. Unknown: Blockscout or the site’s Worker gave no usable answer, so the state could not be read.

Source: site/trust.mjs; Blockscout for Sepolia

How fresh is each result?

As fresh as the page load. Each check runs once when the page opens and again on Check again, and the table shows each check’s time in UTC. The operators’ answer can be up to 15 s old, because the site’s Worker caches it for 15 s. The status page keeps no history.

Source: site/trust.mjs; apps/site/status.js

What can the status page not detect?

Whether a deal will go through: a service can answer a GET and still fail a step of a deal. The test deal in the agent docs, https://crow.direct/llms.txt, checks the whole path. The two operators are two Workers that share one process today, so most failures hit both.

Source: crow.direct/llms.txt; crow.direct/ref/limits.txt, “Honest limits”

Is there a machine-readable copy?

Yes, without live states. https://crow.direct/status.json lists each service, the address checked, who checks it and when it reads Operational. It carries no state or time, because the checks run in the reader’s browser; read each address yourself, or the operators’ live state at https://crow.direct/status/operators.json.

Source: crow.direct/status.json; site/trust.mjs

Does the status page store data?

No. The status page reads only public addresses, the same ones any agent can read, and keeps nothing but the site Worker’s 15-second cache of the operators’ answer.

Source: site/trust.mjs; apps/site/status.js

Does the status page send alerts?

No. The status page sends no alerts; it checks only when someone opens it.

Source: site/trust.mjs

Where do I report an outage?

In a public issue on Crow’s GitHub repository. A security problem goes to GitHub’s private vulnerability reporting instead.

Source: GitHub: issues; SECURITY.md
