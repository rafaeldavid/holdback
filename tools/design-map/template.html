What ’crow is, where it stands, what it needs

What ’crow is

Two AI agents from different firms make a deal without trusting each other. The buyer’s payment and the seller’s work are both held, so neither side can take them alone, until an adjudicator (a judging service the two agents chose) decides whether the work meets the agreed terms.

Then payment and work change hands in one step, or the buyer is refunded.

Holdback is the working name of the protocol underneath. The public demo at escrow.stream uses test tokens only; no real money moves.

    Terms

    Words you will see on this page

    The project uses a small, fixed vocabulary. Each word means one thing everywhere: in the docs, the code and this map.

    Commitment
    The deal itself: terms a buyer agent and a seller agent both sign. It is first offered, then agreed.
    Hold
    The buyer’s payment and the key to the seller’s work, locked together so neither side can take them alone.
    Adjudicator
    A judging service both agents name in the commitment: a primary, a fallback if it goes silent, and one for appeals.
    Panel and judges
    How an adjudicator decides: fixed checks first, then several pinned AI models from at least two model families.
    Bond
    Money an adjudicator puts up. It pays out if an appeal overturns its decision or it misses its deadline.
    Operator node
    A server that offers the API and relays agents’ signed messages. Anyone can run one, and it has no power over a deal.
    Settlement layer
    Where held money sits and the deal rules are enforced. It is a blockchain, kept behind the API so agents never handle it.
    Rules contract
    The program on the settlement layer that releases or refunds a hold. It has no owner and no admin keys.
    SimChain
    An in-process simulation of the settlement layer. The demo runs on it, with test tokens.
    EVM and local chain
    EVM is Ethereum’s virtual machine. Phase 2 runs the rules contract on a private test chain on a developer’s machine.
    tUSD
    The test token. Amounts read like dollars, but none of it is real money.
    ADR
    Architecture decision record: a short document in docs/decisions/ that records a design choice, the options and why.
    D-number
    One decision in docs/decisions-today.md (D1 onward): the question, the options, what was chosen. Larger ones also get an ADR.
    Phase and task
    The plan runs in phases 0 to 11 (docs/plan.md). Each piece of work is a task file in docs/tasks/, named by a T-number.

    Who sees what

    What stays private between buyer, seller and adjudicators

    Every commitment has a public skeleton (addresses, amounts, deadlines, adjudicators, hashes, outcomes) and a private body. The parties choose how much of the body to publish, and the key to the work reaches an adjudicator only when it has to judge (ADR-0020). The demo runs at public; the other levels arrive in Phase 2.

    sees itin part, or only when involveddoes not see it

    Known limits. In guaranteed mode the primary adjudicator reads every delivery (residual 6). The skeleton, including amounts, stays public at every level (residual 9). A funding transfer can link a one-time identity to its source unless it comes from a shielded pool (residual 11). Nobody gets a freeze: compliance screens at admission, reports after the fact and discloses by view key.
